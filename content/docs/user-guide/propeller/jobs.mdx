## Overview

A **Job** is a Kubernetes Job that runs a specific function on a [Proplet](/user-guide/propeller/proplets). The Jobs page is read-only — there's no create, edit, or delete action here. Jobs are submitted outside the UI (via `kubectl`, an API, or the control plane); Propeller's role is to list them and visualize their status.

![Jobs Table](../../img/propeller/jobs-table.png)

## Jobs table

|Column |Description|
|-----------------|------------------------------------------|
|Name |The job's name (click to open its detail page)|
|Status |Current phase: `pending`, `running`, `completed`, or `failed`|
|Function |The function name the job runs|
|Proplet |The Proplet the job is assigned to|
|Start Time |When execution started|
|End Time |When execution finished (blank if still running)|
|Preferred Type |The preferred Proplet type requested for this job|

There's no search, filtering, or tagging on this table — it's a straight list of every job in the workspace.

## Job detail page

Click a job's name to open its detail page (titled **Kubernetes Task Visualization**). Everything here is read-only.

![Job Detail](../../img/propeller/job-detail.png)

**Status Overview** — phase badge, Function, Inputs, Result (if the job produced one), Assigned Proplet, Execution Time (computed from start/finish), and Task ID.

**Metadata** — Name, Created, and Updated timestamps.

**Specification** — Image URL, Function Name, Preferred Proplet Type (defaults to "any" if not set), Inputs, and CLI Arguments (if any were provided).

**Execution Timeline** — the job's Kubernetes conditions, each with a type, status, message, reason, and the time it last transitioned. This is the same condition-history pattern Kubernetes uses for any object.

**Execution Summary** — Started At, Total Duration, and Finished At, formatted for readability.

If the job failed, an **Error** card shows the recorded error message.
