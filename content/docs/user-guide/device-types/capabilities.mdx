What a [Device Type](/user-guide/device-types/introduction) actually declares — its **device attributes** and **commands** — lives on a **version**, not on the type itself. This keeps the declaration immutable: once a version is created, it cannot be edited or have its status changed. To change what a type declares, publish a new version.

Because versions are immutable, a device that's bound to one version keeps validating against exactly that declaration forever — publishing a new version never invalidates devices already deployed against an older one.

## Version status

| Status | Meaning |
|---|---|
| **Draft** | Staged, not yet bindable. Use this to prepare a declaration before exposing it. |
| **Active** | Bindable. Only an active version can be bound to a device. |
| **Deprecated** / **Disabled** | No longer bindable to new devices; devices already bound to it are unaffected. |

Binding without naming a specific version always resolves to the **latest active version**.

## Declaring device attributes

Device attributes are added from a version's editor, under **Device attributes**. Each one has:

- **Label** – the attribute's name.
- **Value type** – number, integer, string, or boolean.
- **Unit** – optional (e.g. `m3`, `%`, `kWh`).
- **Minimum** / **Maximum** – optional numeric range.
- **Allowed values** – optional, comma-separated (e.g. `open, closed`).
- **Placeholder** and **Help text** – optional, shown in the device's own attribute form.

Device attributes are stored on the device and validated on every write — **not** against published telemetry messages. A Device Type constrains what a device's attributes look like, not what it publishes to a channel.

## Declaring commands

Commands are added under **Commands**, each with a **Name**, optional **Description**, and **Parameters** (comma-separated `name:type` pairs, e.g. `interval:integer, mode:string`).

Declaring a command documents that a device of this type accepts it — it does not dispatch or route the command anywhere. Actually sending a command to a device is a separate concern outside Device Types.

## Binding a device to a Device Type

From a device's own page, use `Bind device type` (or `Change device type` if it already has one) to select a Device Type and, optionally, a specific version — leaving the version unselected binds to the type's latest active version.

A device with no Device Type bound shows as **Not bound to a device type** and accepts any attributes.

A binding change takes effect starting with the device's *next* write: the write in progress at the time of the change still validates against whichever version the device was bound to before the change. There is no way to unbind a device from a Device Type once bound — only to bind it to a different one.
