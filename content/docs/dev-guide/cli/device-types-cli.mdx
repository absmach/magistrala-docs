The `devicetypes` command manages [Device Types](/user-guide/device-types/introduction): named, versioned declarations of what a class of device measures and accepts. It wraps the platform's Atom-backed device type API directly — there is deliberately no delete operation, since a type is retired by changing its status, not removed.

Listing is always workspace-scoped — `all get` still requires a `<workspace_id>`.

### Create a Device Type

```bash
magistrala-cli devicetypes create '{"key":"thermostat","name":"Thermostat"}' <workspace_id>
```

Creates the type only. Its device attributes and commands are added separately, via `create-version` below.

### List Device Types

```bash
magistrala-cli devicetypes all get <workspace_id>
```

### Get a Device Type

```bash
magistrala-cli devicetypes <device_type_id> get
```

### Update a Device Type

```bash
magistrala-cli devicetypes <device_type_id> update '{"name":"Thermostat","status":"deprecated"}'
```

`status` is one of `active`, `deprecated`, or `disabled`. A non-active type refuses new bindings; devices already bound to it are unaffected.

### List a Device Type's versions

```bash
magistrala-cli devicetypes <device_type_id> versions
```

### Create a version

```bash
magistrala-cli devicetypes <device_type_id> create-version '{"capabilities":{"measurements":[{"name":"temperature","type":"number","unit":"Cel"}]}}'
```

A version is immutable once created — status included. Create it with `"status":"draft"` in the body to stage a declaration without making it bindable. `capabilities` accepts `measurements` and `commands`; see the [Device Attributes, Commands, and Versions](/user-guide/device-types/capabilities) user-guide page for the full field set.

### Get the active version

```bash
magistrala-cli devicetypes <device_type_id> active-version
```

Returns the highest-numbered version with `status: active` — the version a bind resolves to when no version is named explicitly.

### Bind a device

```bash
magistrala-cli devicetypes <device_type_id> bind <device_id> <version_id>
```

`version_id` is optional — omitting it binds to the type's active version. `bind` is the checked way to attach a device to a type: it refuses a type or version that isn't active. Setting `device_type_id` directly through `devices <device_id> update` instead skips that check.
