# v0.51.0 image preservation handoff

**Status: not yet done. Nothing has been uploaded or copied — this is a to-do list for whoever has R2 write access.**

## Why

Doc images/diagrams/screenshots are served from the shared `websites-images` R2 bucket, not committed to git (see `README.md`'s "Deploying images and diagrams"). `latest` (`main`) reads and writes the **unversioned** prefix `magistrala-docs/{img,diagrams,screenshots}/...` and will keep changing it as the Latest documentation overhaul replaces stale screenshots.

The `v0.51.0` branch's Worker (`workers/image-proxy.ts`) has already been forked to read from a separate, **version-scoped** prefix instead: `magistrala-docs/v0-51-0/{img,diagrams,screenshots}/...`. That prefix does not exist yet. Until it's populated, every image on the `v0.51.0` deployment 404s. Populating it once, now, with a copy of everything `main` currently references is what makes `v0.51.0` immutable — after this copy, nothing Latest does to the unversioned prefix can ever change what `v0.51.0` displays.

This is a **one-time bulk copy inside R2** (object to object, no local download/re-upload of image bytes) — not a use of `scripts/publish-image.mjs` (that script only writes to the unversioned prefix and is not meant to be pointed at a versioned one).

## What to copy

Copy every object under these three source prefixes to the matching destination prefix, preserving the relative path:

| Source prefix (bucket `websites-images`) | Destination prefix |
|---|---|
| `magistrala-docs/img/` | `magistrala-docs/v0-51-0/img/` |
| `magistrala-docs/diagrams/` | `magistrala-docs/v0-51-0/diagrams/` |
| `magistrala-docs/screenshots/` | `magistrala-docs/v0-51-0/screenshots/` |

The full list below (535 objects: 471 `img/`, 20 `diagrams/`, 44 `screenshots/`) was generated by resolving every markdown image reference in `content/docs/**` at the `v0.51.0` snapshot commit (`e392db813f33bd46db434334d25df9932de51c64`) through the same path-resolution rules as `lib/remark-doc-images.ts`. It's provided so the copy can be verified for completeness — it is *not* meant to be typed in one object at a time.

## Recommended method: `rclone`, not `wrangler r2 object`

`wrangler r2 object` only gets/puts one object per invocation and has no server-side copy — for 535 objects that means 535 round trips through this machine. R2 is S3-compatible, so `rclone` (configured with an R2 S3 remote) can do a true prefix-to-prefix bulk copy in three commands, entirely server-side:

```bash
# One-time rclone remote setup (R2 S3-compatible endpoint):
# rclone config create r2 s3 provider=Cloudflare \
#   access_key_id=<R2_ACCESS_KEY_ID> secret_access_key=<R2_SECRET_ACCESS_KEY> \
#   endpoint=https://<ACCOUNT_ID>.r2.cloudflarestorage.com

rclone copy r2:websites-images/magistrala-docs/img        r2:websites-images/magistrala-docs/v0-51-0/img
rclone copy r2:websites-images/magistrala-docs/diagrams   r2:websites-images/magistrala-docs/v0-51-0/diagrams
rclone copy r2:websites-images/magistrala-docs/screenshots r2:websites-images/magistrala-docs/v0-51-0/screenshots
```

R2 API tokens for `rclone`'s S3-compatible access are separate from the `CLOUDFLARE_API_TOKEN` used by `scripts/publish-image.mjs` (which uses `wrangler r2 object put`, a different auth path) — create one under **R2 → Manage API Tokens** with Object Read & Write on `websites-images`.

If `rclone` isn't available, the fallback is a small script looping `wrangler r2 object get <src> --remote --file=/tmp/x` then `wrangler r2 object put <dest> --remote --file=/tmp/x --content-type=<mime>` per line of the lists below — correct but slow and easy to get out of sync on content-type; prefer `rclone`.

## After copying: verify

Spot-check a handful of URLs resolve on the `v0.51.0` deployment once it's live (or against the bucket directly via `wrangler r2 object get`), e.g.:

```bash
wrangler r2 object get websites-images/magistrala-docs/v0-51-0/img/domain/domain-homepage.png --remote --file=/tmp/check.png
wrangler r2 object get websites-images/magistrala-docs/v0-51-0/screenshots/solutions/solution-packs.png --remote --file=/tmp/check2.png
```

A cheap completeness check is comparing object counts per prefix (471 / 20 / 44) against `rclone size r2:websites-images/magistrala-docs/v0-51-0/img` etc.
